# Hard rules (do not violate)

Every rule that governs an authored rule, with the reasoning and the lint code that enforces it
where one does. Four of these stay on the card because they are cheap to state and expensive to
miss; the rest are here because the card reached its ceiling and the project's standard names two
honest moves at that point -- move prose to a reference, or move the subject to its own skill.

Moving them did not soften them. "Do not violate" means the same thing in a reference.

- Terminate a capture on CONTENT, not on the end of the line, wherever the value will be COMPARED rather than displayed. A capture running to end-of-line inherits any trailing space the device wrote, and the field then reads correctly everywhere except under exact comparison, where a filter returns zero rows rather than an error. Use `(.*\S)`. This matters most for `xdm.target.process.command_line` and `xdm.event.original_event_type`, the two natural correlation keys; a free-text description legitimately wants the tail. A delimiter-closed capture is safe against whitespace OUTSIDE the delimiter but not INSIDE it, so bound the capture on the CONTENT it must contain. WARN-054 covers the end-of-line form only. See [references/process-mapping.md](process-mapping.md).
- Never let letter case qualify a capture; structure must. XQL matches case-insensitively everywhere, so `[A-Z]` also matches lowercase and an uppercase character class does NOT restrict what a group captures. A pattern relying on the class to mean "this is a vendor tag, not prose" takes whatever token occupies that position, and the field ends up holding a plausible but WRONG value -- a fourth failure mode beyond null, empty and the catch-all sentinel, and the only one no count reveals. Anchor every capture on structure that identifies the token. Where the position genuinely is free text, enumerate the documented vendor tags in an alternation and let anything else fall back -- documented vendor tags are not the sample-derived literals WARN-049 forbids. WARN-052 flags a case-qualified capture with no literal anchor. See [references/xql-language.md](xql-language.md).
- Always map a const-typed enum over its COMPLETE set, never just the values the sample showed. `xdm.network.http.response_code` is the canonical case: render the full crosswalk with `python3 scripts/http_status_map.py --render`, because a production source returns codes the sample never contained and a partial chain silently drops them (WARN-048). The same principle holds for any const field whose full membership is known.
- For an endpoint / process / file / registry / image event, classify on three fields, not one label: the raw channel / source label in `xdm.event.type`, the per-record semantic name in `xdm.event.original_event_type`, and the precise verb in `xdm.event.operation` from the 56-member `XDM_CONST.OPERATION_TYPE_*` enum. Do NOT leave the operation blank when a verb fits, and do NOT stuff a semantic string into `xdm.event.type`. Endpoint events carry blank `xdm.event.tags` -- there is no process story tag -- yet are fully modelled, so they do NOT take the `GOCORTEX_UNMODELLED` catch-all. See [references/process-mapping.md](process-mapping.md).
- For a cloud audit source, DERIVE `xdm.event.operation` from the provider's action-naming convention (CloudTrail `eventName` prefix, Azure `operationName` suffix, GCP `methodName` verb) rather than hardcoding the actions the sample showed, and keep the raw action in `xdm.event.original_event_type`. Map `xdm.*.cloud.provider` reliably; set `xdm.*.cloud.service` (`CLOUD_SERVICE_TYPE`) only on a confident known match, otherwise keep the raw service name in `xdm.event.type` / `xdm.event.description` or NOT MAPPED. NEVER assign `xdm.*.cloud.source_type` -- it is banned. See [references/cloud-mapping.md](cloud-mapping.md).
- Never hardcode a value that came from the sample. A tenant URL path, hostname, IP, ID or product-specific token must NOT be baked into a `contains "..."` branch or an `= "..."` assignment -- that leaks customer-internal data into the rule and does not scale beyond what the sample happened to show (WARN-049). Extract it dynamically or keep the raw value in a free-String XDM field. Only hardcode `XDM_CONST` members, the observer vendor / product identity, and well-known vendor-agnostic tokens. Never invent a classification the source does not define -- see [references/transformation-patterns.md](transformation-patterns.md).
- Never use infix arithmetic inside `alter`. Use `add()`, `subtract()`, `multiply()`, `divide()` -- see [references/parser-idioms.md](parser-idioms.md) (ERR-012).
- Never assign a raw numeric score to `xdm.alert.severity`. Apply banded scoring per [references/transformation-patterns.md](transformation-patterns.md).
- Never echo a log-level word into `xdm.alert.severity`. Words like `warning`, `error`, `notice`, `debug` are syslog levels, not severity bands. Band them to Informational / Low / Medium / High / Critical and map the raw level to `xdm.event.log_level` (WARN-037).
- Always end a categorical if-chain into a free-String XDM field that carries vendor text (`xdm.alert.subcategory`, `xdm.observer.action`, `xdm.alert.original_threat_name`, and similar) with a `tmp_field != null, tmp_field` passthrough, so an unmapped vendor value is preserved rather than silently nulled. This does NOT apply to closed-list `XDM_CONST` targets (omit the default, giving null) nor to band-vocabulary fields like `xdm.alert.severity`.
- Always emit the MAPPED header. It is the required prefix for every rule -- see [references/modeling-rules.md](modeling-rules.md) and [assets/modeling_header_template.xql](../assets/modeling_header_template.xql).
- Always use British English in comments (normalise, analyse, behaviour, colour).
